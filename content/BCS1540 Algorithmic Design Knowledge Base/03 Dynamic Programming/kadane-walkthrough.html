Step 1 of 4

Define the table of values

What is a "table of values"?

A table of values is an array — 1-dimensional, 2-dimensional, or higher — where each cell stores the answer to a sub-problem. We solve the original problem by computing all the sub-problems' answers, one cell at a time.

It's called a "table" because, when the table is 2D, it visually looks like a grid (rows × columns). But the data structure is just an array.

What goes in a cell?

A single number — specifically the optimum value (max sum, min cost, count, etc.) for some sub-problem. Not the solution itself (e.g. the actual subarray), just the value. Reconstructing the actual solution is done separately in Step 4.

What's a "sub-problem"?

A smaller version of the original problem. For DP to work, the original problem must have natural smaller pieces that can be solved independently and combined.

For our Kadane problem, the original question is: "What's the max-sum contiguous subarray of X[1..n]?" A natural smaller piece is: "What's the max-sum subarray ending at index j?" That's a sub-problem — one per choice of j.

How do you find the right table definition?

Ask yourself: "What's the LAST decision the algorithm makes? What parameters describe a sub-problem just before that decision?" Those parameters become the indices of your table.

For Kadane: the last decision is "where does the subarray end?". Parameter = j (the ending index). So the table is indexed by j — a 1D table.

  • If the last decision involves one parameter → 1D table (Kadane, Weighted Interval Scheduling)
  • Two parameters → 2D table (Knapsack: which items × remaining capacity; LCS: prefix-of-string1 × prefix-of-string2)
  • More → higher-dimensional table (TSP uses a subset + last vertex)

How do you DEFINE it on paper?

Write one sentence in the exact form:

Let OPT[index] = the [max / min / count] of [property] over [sub-problem description].

For Kadane:

Definition: OPT[j] = the maximum sum of a contiguous subarray ending at index j, for j = 1, …, n.

Whole-problem mapping: the answer to the original problem is max over j ∈ {1, …, n} of OPT[j].

Notice: the table doesn't directly give the answer — instead, the answer is the max of all table cells. That's fine. Many DP problems work this way.

Common pitfall: defining OPT[i, j] = "max-sum subarray from i to j". That's just restating the original problem with extra parameters. It gives no obvious smaller sub-problem. The right table is anchored to a SINGLE decision point (here: where the subarray ends).
Common pitfall: forgetting to state that the whole problem's answer is max/min over cells. The grader needs to see how the table corresponds to the final answer.
Step 2 of 4

Give the recurrence (with correctness justification)

What is a "recurrence"?

A recurrence is a formula that expresses OPT[i] in terms of OPT[smaller indices] — together with base cases for the smallest sub-problems where no recursion is needed.

How do you FIND the recurrence?

Step back and ask: "For an optimal solution to sub-problem i, what's the LAST decision it makes?" Usually there are 2–3 options. List them, take the max (or min, or sum) over the options.

For Kadane's OPT[j]: the best subarray ending at j has a "starting position". Two options:

  • Option A — Start fresh at j. Subarray length 1, just X[j].
  • Option B — Extend a subarray ending at j-1. Length ≥ 2, equals (best subarray ending at j-1) + X[j].

Any subarray ending at j must be one of these two cases — there's no other possibility.

Write the recurrence:

Recurrence: OPT[j] = max( X[j],   X[j] + OPT[j-1] ) for j ≥ 2.
Base case: OPT[1] = X[1].

Justifying correctness

The grader wants you to explain why the recurrence is correct. One sentence is enough:

Correctness: any contiguous subarray ending at j either has length 1 (= X[j] alone) or has length ≥ 2 (= some subarray ending at j-1, extended by X[j]). The recurrence considers both cases and picks the maximum, so it equals the max-sum subarray ending at j.

The recipe: list the cases that any optimal sub-problem solution can take, observe the recurrence considers all of them, conclude correctness.

Common pitfall: forgetting the base case. Without OPT[1] = X[1], the recurrence has nothing to start from.
Common pitfall: using "any subarray ending at j-1" in Option B instead of "the BEST subarray ending at j-1" (= OPT[j-1]). The recurrence MUST refer to optimal sub-problem solutions, not arbitrary ones. This is the principle of "optimal substructure".
Step 3 of 4

Bottom-up algorithm + runtime

What does "bottom-up" mean?

It means compute the table values starting from the smallest sub-problems, building up to the full problem. The opposite is "top-down" (recursive, with memoisation) — same result, but bottom-up is iterative and standard on the exam.

How do you find the right ORDER to fill cells?

Look at the recurrence. Each cell OPT[i] depends on some smaller-indexed cells. Fill cells in an order such that whenever you compute OPT[i], all the cells it depends on are already filled.

For Kadane: OPT[j] depends on OPT[j-1] only. So fill in order j = 1, 2, …, n.

For 2D tables: usually nested loops, with the outer loop being the parameter that drives smaller-to-larger.

Write the algorithm:

KADANE(X[1..n]):
    OPT[1] := X[1]
    for j := 2 to n:
        OPT[j] := max(X[j], X[j] + OPT[j-1])
    answer := max over j of OPT[j]
    return answer

Runtime analysis

Always state runtime explicitly, in the form:

Runtime = O( (number of table cells) × (work per cell) ) = O(...)

For Kadane:

  • Number of cells: n
  • Work per cell: O(1) (just one comparison)
  • Plus O(n) for the final max-scan
  • Total: O(n)

Compare to brute force: try all O(n²) subarrays, each summed in O(n) → O(n³). DP cuts this by a factor of n².

Common pitfall: stating runtime as a single big-O without breaking down where it comes from. Graders want to see the (table size × work) reasoning.
Step 4 of 4

Reconstruction — recover the actual solution

What is reconstruction?

After Step 3, you have all the table values, including the optimum value. But you usually don't have the actual SOLUTION — the set of choices that produces the optimum. Reconstruction recovers it.

For Kadane: Step 3 gives you the max sum (a number, 6). Reconstruction gives you the actual indices (i, j) of the subarray achieving sum 6.

How do you reconstruct?

Walk back through the table starting from the "winning" cell. At each cell, figure out which branch of the recurrence "won" — that is, which option in the max/min produced this cell's value. Record the choice, then jump to the predecessor cell suggested by that option. Continue until you reach a base case.

For Kadane:

Start: find j* = argmax OPT[j] (the right endpoint of the best subarray).

Walk back from j* to find the left endpoint i*. At each cell OPT[i], ask: which branch produced this value?

  • If OPT[i] = X[i] + OPT[i-1] → Option B was used (extended). Keep walking left.
  • Otherwise → Option A was used (started fresh). Stop — i is the left endpoint.
RECONSTRUCT(OPT, X):
    j* := index achieving max over j of OPT[j]
    i* := j*
    while i* > 1 and OPT[i*] = X[i*] + OPT[i*-1]:
        i* := i* - 1
    return (i*, j*)

For our example: j* = 7 (OPT[7] = 6 is max). Walking back: i*=7 → extended → 6 → extended → 5 → extended → 4 → NOT extended (started fresh). Stop at i* = 4. Answer: subarray X[4..7] = [4, -1, 2, 1], sum 6.

Runtime

O(n) for the backward walk plus O(n) to find j* = O(n) total. Always state it.

Common pitfall: stopping reconstruction at j* without walking back. Step 4 is not just "find the winning cell" — it's "find the actual solution structure".
Common pitfall: forgetting to track which branch won. Sometimes you need extra information (e.g., for LCS, you remember which of three branches: match / drop-from-s1 / drop-from-s2). For Kadane the comparison OPT[i] = X[i] + OPT[i-1] suffices.

📋 The full 4-step answer (18 pts on the exam)

Step 1. Define the table.
    Let OPT[j] be the maximum sum of a contiguous subarray ending at
    index j, for j = 1, ..., n. The whole problem's answer is
    max over j of OPT[j].

Step 2. Recurrence + correctness.
    OPT[j] = max( X[j],  X[j] + OPT[j-1] ) for j >= 2.
    Base case: OPT[1] = X[1].
    Correctness: any subarray ending at j either has length 1 (just X[j])
    or length >= 2 (a subarray ending at j-1, extended by X[j]). The
    recurrence considers both options and picks the larger, so it
    equals the max-sum subarray ending at j.

Step 3. Bottom-up + runtime.
    OPT[1] := X[1]
    for j := 2 to n:
        OPT[j] := max(X[j], X[j] + OPT[j-1])
    answer := max over j of OPT[j]
    Runtime: O(n) cells with O(1) work each, plus O(n) for the final
    max = O(n) total.

Step 4. Reconstruction.
    j* := index achieving max over j of OPT[j]
    i* := j*
    while i* > 1 and OPT[i*] = X[i*] + OPT[i*-1]:
        i* := i* - 1
    return (i*, j*)
    Runtime: O(n).
