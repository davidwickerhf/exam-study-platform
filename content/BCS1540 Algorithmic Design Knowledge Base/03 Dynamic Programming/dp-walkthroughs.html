The 4-step format is what you literally write on the exam. Below each step is explained with examples from 4 canonical DP problems (Kadane / WIS / LCS / Knapsack), so you can see the format flex across different problem shapes.
Step 1 of 4

Define the table of values

What is a "table of values"?

An array — 1D, 2D, or higher — where each cell stores the answer to a sub-problem. We solve the original problem by computing all the sub-problems' answers, one cell at a time.

What goes in a cell?

The optimum value (max sum / min cost / count) for that sub-problem. Not the solution itself; just the value. Reconstructing the actual solution happens in Step 4.

How to find the right indices?

Ask: "What's the LAST decision the algorithm makes? What parameters describe a sub-problem just before that decision?" Those parameters become the indices.

How to define on paper?

Let OPT[indices] = [max / min / count] of [property] over [sub-problem description].

Examples across canonical DPs

Kadane (max subarray sum) Table: 1D, indexed by ending position j.
Let OPT[j] = max sum of a contiguous subarray ending at index j.
Whole problem: answer = max over j of OPT[j].
Weighted Interval Scheduling Table: 1D, indexed by interval count i (after sorting by finish time).
Let OPT[i] = max total benefit using a subset of the first i intervals.
Whole problem: OPT[n] directly.
LCS (longest common subsequence) Table: 2D, indexed by prefix lengths of the two strings.
Let L[i][j] = length of the LCS of s1[1..i] and s2[1..j].
Whole problem: L[n][m] directly (or rebuild the string itself by reconstruction).
0/1 Knapsack Table: 2D, indexed by (items considered, capacity).
Let OPT[j][Z] = max total value using a subset of the first j items with total weight ≤ Z.
Whole problem: OPT[n][W] directly.
Pitfall: defining the table to be the WHOLE problem (no smaller sub-problem). Make sure each cell is strictly smaller than the next.
Pitfall: forgetting to state how the table relates to the whole-problem answer (max over cells, or a specific cell).
Step 2 of 4

Give the recurrence (with correctness)

What is a recurrence?

A formula expressing OPT[i] in terms of OPT[smaller indices] + base cases.

How to find it?

Ask: "For an optimal solution to sub-problem i, what's the LAST decision? List 2–3 options, take max/min."

Examples

Kadane (max subarray sum) Last decision: does the best subarray ending at j include only X[j], or extend X[j-1]?
OPT[j] = max( X[j],  X[j] + OPT[j-1] )
Base: OPT[1] = X[1]
Correctness: any subarray ending at j either starts at j (length 1) or extends a subarray ending at j-1. Both options considered.
Weighted Interval Scheduling Last decision: include interval i, or skip it?
OPT[i] = max( OPT[i-1],  b_i + OPT[p(i)] )
Base: OPT[0] = 0
where p(i) = largest index j < i with interval j compatible with i.
Correctness: any optimal solution either uses interval i (forces the compatible-predecessor branch) or doesn't (reduces to OPT[i-1]).
LCS (longest common subsequence) Last decision: at position (i, j), do the last characters match — if so, do we use them?
L[i][j] = 1 + L[i-1][j-1]            if s_1[i] == s_2[j]
        = max( L[i-1][j], L[i][j-1] ) otherwise
Base: L[0][*] = L[*][0] = 0
Correctness: either the last characters of both strings are in the LCS (forces match branch) or one of them is dropped.
0/1 Knapsack Last decision: take item j, or skip it?
OPT[j][Z] = max( OPT[j-1][Z],
                  v_j + OPT[j-1][Z - w_j]  if w_j ≤ Z )
Base: OPT[0][Z] = 0 for all Z
Correctness: either item j is in the optimal subset (consumes its weight) or it isn't.
Pitfall: forgetting the base case (no recursion can terminate).
Pitfall: using "any" sub-problem solution in the recurrence rather than the optimal one — this breaks the "optimal substructure" guarantee.
Step 3 of 4

Bottom-up algorithm + runtime

What does "bottom-up" mean?

Compute table values starting from the smallest sub-problems and build up to the full problem. The order must respect dependencies (each cell's predecessors are already computed).

Runtime formula

Runtime = O( (number of cells) × (work per cell) )

Examples

Kadane 
OPT[1] := X[1]
for j := 2 to n:
    OPT[j] := max(X[j], X[j] + OPT[j-1])
answer := max over j of OPT[j]
Cells: n, work per cell: O(1) → O(n) total.
Weighted Interval Scheduling 
sort intervals by finish time
compute p(i) for each i  // via binary search
OPT[0] := 0
for i := 1 to n:
    OPT[i] := max(OPT[i-1], b_i + OPT[p(i)])
return OPT[n]
Sort: O(n log n). Compute p(i): O(n log n). Fill: O(n). Total: O(n log n).
LCS 
for i := 0 to n: L[i][0] := 0
for j := 0 to m: L[0][j] := 0
for i := 1 to n:
    for j := 1 to m:
        if s_1[i] == s_2[j]:
            L[i][j] := 1 + L[i-1][j-1]
        else:
            L[i][j] := max(L[i-1][j], L[i][j-1])
return L[n][m]
Cells: nm, work per cell: O(1) → O(nm) total.
0/1 Knapsack 
for Z := 0 to W: OPT[0][Z] := 0
for j := 1 to n:
    for Z := 0 to W:
        skip := OPT[j-1][Z]
        take := (Z ≥ w_j) ? v_j + OPT[j-1][Z - w_j] : -∞
        OPT[j][Z] := max(skip, take)
return OPT[n][W]
Cells: n × (W+1), work per cell: O(1) → O(nW) total.

Pseudopolynomial: input size is O(n log W), but runtime is O(nW) — exponential in log W. Knapsack is NP-complete; this is best we can do.
Pitfall: stating runtime as a single big-O without breaking down where it comes from (cells × work per cell).
Step 4 of 4

Reconstruction — recover the actual solution

What is reconstruction?

Walk back through the filled table to extract the actual decisions (not just the optimal value).

How?

Start at the winning cell. At each cell, determine which branch of the recurrence "won". Record the choice, jump to the predecessor cell suggested by that branch. Continue until a base case.

Examples

Kadane (recover indices) 
j* := argmax_j OPT[j]
i* := j*
while i* > 1 and OPT[i*] = X[i*] + OPT[i*-1]:
    i* := i* - 1
return (i*, j*)
O(n). Identifies which branch (extend or start-fresh) won at each step.
Weighted Interval Scheduling (recover selected intervals) 
selected := empty
i := n
while i > 0:
    if OPT[i] > OPT[i-1]:
        // "take i" branch won
        selected.add(i)
        i := p(i)
    else:
        i := i - 1
return selected
O(n). At each step decide if interval i was taken (compared to skipping).
LCS (recover the actual common subsequence string) 
i := n; j := m; result := empty
while i > 0 and j > 0:
    if s_1[i] == s_2[j]:
        // match: this char is in LCS
        result.prepend(s_1[i])
        i := i - 1; j := j - 1
    elif L[i-1][j] >= L[i][j-1]:
        i := i - 1
    else:
        j := j - 1
return result
O(n + m). At each cell, find which of three branches the recurrence took.
0/1 Knapsack (recover selected items) 
items := empty
j := n; Z := W
while j > 0:
    if OPT[j][Z] > OPT[j-1][Z]:
        // item j was taken
        items.add(j)
        Z := Z - w_j
    j := j - 1
return items
O(n). Compare with the "skip" branch to detect if item j was taken.
Pitfall: giving only the optimum VALUE without reconstructing the actual decisions. The exam asks for both.

Problem A — Take/Skip with adjacency

House Robber

You're planning to rob houses along a street. House i contains vi coins (positive integer). The police are tipped off if you rob two adjacent houses on the same night. Maximise total coins.

Example: Houses with values [2, 7, 9, 3, 1]. Best plan: rob houses 1, 3, 5 → 2 + 9 + 1 = 12. Houses 2, 4 → 10. Optimal = 12.

Your attempt

🔍 Pattern recognition

Pattern: Take / Skip with a simple compatibility predecessor.

Last decision: "For house i, take it or skip it. If take, the previous taken house was at most i-2."

Similar to: Weighted Interval Scheduling, but the "compatible predecessor" is constant (always i-2) instead of computed via binary search.

📋 Model 4-step answer 
Step 1. Define the table.
   Let OPT[i] = max coins robbed using a subset of houses 1, 2, ..., i
   with no two adjacent. Whole-problem answer = OPT[n].

Step 2. Recurrence + correctness.
   OPT[i] = max( OPT[i-1],          // skip house i
                 v_i + OPT[i-2] )   // rob house i (can't rob i-1)
   Base: OPT[0] = 0, OPT[1] = v_1.
   Correctness: any optimal solution either includes house i (forcing
   previous taken house ≤ i-2) or excludes it (reducing to OPT[i-1]).

Step 3. Bottom-up + runtime.
   OPT[0] := 0; OPT[1] := v_1
   for i := 2 to n:
       OPT[i] := max(OPT[i-1], v_i + OPT[i-2])
   return OPT[n]
   Runtime: O(n) cells × O(1) work = O(n).

Step 4. Reconstruction.
   robbed := empty; i := n
   while i > 0:
       if i == 1 or OPT[i] > OPT[i-1]:    // robbed house i
           robbed.add(i); i := i - 2
       else:                                // skipped house i
           i := i - 1
   return robbed
   Runtime: O(n).
Problem B — Match/Drop with 3 options

Edit Distance (Levenshtein)

Given two strings s1 (length n) and s2 (length m), find the minimum number of single-character edits to transform s1 into s2. Allowed edits: insertion, deletion, substitution.

Example: Transform "kitten" into "sitting". Minimum = 3 edits: substitute 'k'→'s', substitute 'e'→'i', insert 'g' at end.

Your attempt

🔍 Pattern recognition

Pattern: Match / Drop (LCS family), with 3 branches in the no-match case (insert, delete, substitute).

Last decision: "At positions (i, j), what was the LAST edit operation?" — match (no edit), substitute, insert, or delete.

Similar to: LCS, but with insert/delete/substitute instead of just drop-from-one.

📋 Model 4-step answer 
Step 1. Define the table.
   Let E[i][j] = min number of edits to transform s_1[1..i] into s_2[1..j],
   for 0 ≤ i ≤ n, 0 ≤ j ≤ m. Whole-problem answer = E[n][m].

Step 2. Recurrence + correctness.
   E[i][j] = E[i-1][j-1]                            if s_1[i] = s_2[j]
           = 1 + min( E[i-1][j],     // delete s_1[i]
                      E[i][j-1],     // insert s_2[j] into s_1
                      E[i-1][j-1] )  // substitute s_1[i] -> s_2[j]
                                                    otherwise
   Base: E[i][0] = i, E[0][j] = j.
   Correctness: the last operation is one of {match, delete, insert,
   substitute}, each reducing to a smaller subproblem.

Step 3. Bottom-up + runtime.
   for i := 0 to n: E[i][0] := i
   for j := 0 to m: E[0][j] := j
   for i := 1 to n:
       for j := 1 to m:
           if s_1[i] = s_2[j]:
               E[i][j] := E[i-1][j-1]
           else:
               E[i][j] := 1 + min(E[i-1][j], E[i][j-1], E[i-1][j-1])
   return E[n][m]
   Runtime: O(nm) cells × O(1) work = O(nm).

Step 4. Reconstruction (recover the edit operations).
   i := n; j := m; ops := empty
   while i > 0 or j > 0:
       if i > 0 and j > 0 and s_1[i] = s_2[j]:
           i--; j--    // match, no edit
       elif i > 0 and j > 0 and E[i][j] = 1 + E[i-1][j-1]:
           ops.prepend("substitute s_1[i] -> s_2[j]"); i--; j--
       elif i > 0 and E[i][j] = 1 + E[i-1][j]:
           ops.prepend("delete s_1[i]"); i--
       else:
           ops.prepend("insert s_2[j]"); j--
   return ops
   Runtime: O(n + m).
Problem C — Previous State

Longest Increasing Subsequence (LIS)

Given an array a[1..n] of integers, find the length of the longest strictly increasing subsequence (not necessarily contiguous).

Example: a = [10, 9, 2, 5, 3, 7, 101, 18]. LIS = [2, 3, 7, 18] or [2, 3, 7, 101], length 4.

Your attempt

🔍 Pattern recognition

Pattern: Previous State — the LIS ending at i extends some LIS ending at a previous j with a[j] < a[i].

Last decision: "Which earlier element j is the previous element of the LIS ending at i?" — could be ANY j < i with a[j] < a[i].

Key difference from Kadane: the "previous" isn't just i-1 — it's any earlier valid element. Each cell scans all earlier cells, giving O(n²).

📋 Model 4-step answer 
Step 1. Define the table.
   Let OPT[i] = length of the longest strictly increasing subsequence
   ending at index i (must include a[i]).
   Whole-problem answer = max over i of OPT[i].

Step 2. Recurrence + correctness.
   OPT[i] = 1 + max{ OPT[j] : j < i and a[j] < a[i] }
          = 1   if no such j exists
   Base: OPT[1] = 1 (just a[1] alone).
   Correctness: the LIS ending at i either has length 1 (just a[i]) or
   extends some shorter LIS ending at an earlier j with a[j] < a[i].
   We take the maximum over all valid predecessors.

Step 3. Bottom-up + runtime.
   OPT[1] := 1; parent[1] := nil
   for i := 2 to n:
       OPT[i] := 1; parent[i] := nil
       for j := 1 to i-1:
           if a[j] < a[i] and OPT[j] + 1 > OPT[i]:
               OPT[i] := OPT[j] + 1
               parent[i] := j
   return max over i of OPT[i]
   Runtime: O(n²) (each cell scans all earlier cells).

Step 4. Reconstruction (recover the LIS itself).
   i* := argmax over i of OPT[i]
   result := empty
   while i* != nil:
       result.prepend(a[i*])
       i* := parent[i*]
   return result
   Runtime: O(n).
Problem D — Take/Skip with repetition

Coin Change (Minimum Coins)

Given coin denominations C = {c1, …, ck} (positive integers) and a target amount T, find the minimum number of coins (with repetition allowed) that sum to exactly T. Return ∞ if impossible.

Example: C = {1, 4, 5}, T = 8. Min coins = 2 (4 + 4). Greedy by largest denomination gives 5+1+1+1 = 4 coins — suboptimal.

Your attempt

🔍 Pattern recognition

Pattern: Take/Skip with repetition (unbounded knapsack family).

Last decision: "What was the LAST coin added to reach amount Z?" — try each denomination c, then we had to reach Z-c with minimum coins.

Why greedy fails: Greedy by largest denomination doesn't always work — see the example with C = {1, 4, 5}, T = 8.

📋 Model 4-step answer 
Step 1. Define the table.
   Let OPT[Z] = min number of coins summing to exactly Z,
   for 0 ≤ Z ≤ T. Whole-problem answer = OPT[T]
   (or report ∞ = impossible).

Step 2. Recurrence + correctness.
   OPT[Z] = 1 + min{ OPT[Z - c] : c ∈ C and c ≤ Z }
          = ∞   if no c ≤ Z exists
   Base: OPT[0] = 0 (need 0 coins to make amount 0).
   Correctness: any optimal way to make Z uses some last coin c;
   before adding it, we'd made amount Z - c with minimum coins.
   We try all denominations and take the min.

Step 3. Bottom-up + runtime.
   OPT[0] := 0
   for Z := 1 to T: OPT[Z] := ∞
   lastCoin[0] := nil
   for Z := 1 to T:
       for each c in C:
           if c ≤ Z and 1 + OPT[Z - c] < OPT[Z]:
               OPT[Z] := 1 + OPT[Z - c]
               lastCoin[Z] := c
   return OPT[T]
   Runtime: O(k · T) — k denominations × T table cells, O(1) per check.

Step 4. Reconstruction (which coins were used).
   coins := empty; Z := T
   while Z > 0:
       coins.add(lastCoin[Z])
       Z := Z - lastCoin[Z]
   return coins
   Runtime: O(answer) ≤ O(T).
