# Sign-in handoff

Sign-in is self-hosted Better Auth at `/api/auth/*` (see README, Hosted sign-in). An active session replaces the sign-in/sign-up form with an explicit workspace handoff. The requested `/app/...`, `/connect` or `/connect/remote` destination is retained through sign-in, sign-up, email verification and Google; external, API and recursive auth destinations fall back to `/app`. A slow load displays a retry action rather than an empty form area.

The session is a first-party HttpOnly cookie, so the workspace sends no tokens. Its fetch wrapper only watches same-origin `/api/*` responses: the pre-handler `Sign in required` envelope (session expired, revoked by a password reset, or the account deleted) signs the browser out and returns to `/sign-in` with the current destination. Arbitrary provider 401s and 403 eligibility responses are left to the page. Pending requests are fenced against account changes, and unmounting restores the original fetch function.

The entry gate reads `/api/onboarding/status`, which returns only `finished`. Explicitly completed/skipped setup reads the stored completion marker without reading academic sources. Legacy established accounts use an account-scoped programme/course-existence query. Document reconciliation, transcript versions, Canvas connections and course-rule scans remain on the full setup page, where they are useful. The verdict retains the same semantics as `/api/onboarding`.
