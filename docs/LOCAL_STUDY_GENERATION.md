# Local study generation

The source picker can prepare a private guide for a local agent. The reader shows a copyable continuation instruction, polls for accepted chapters, and lets the student pause. Source refreshes stay local; a hosted retry/improvement cannot silently switch billing.

MCP 2.11.0 adds eight `study_generation_*` tools. Start with the live contract and source inventory, create a run, then alternate next/submit until completion. `canvas_import_remote_course` already downloads originals through the authorised proxy without exposing Canvas credentials. Supplementary OCR/visual interpretation can be submitted as explicitly labelled local notes with original filenames and page numbers. It does not overwrite trusted originals.

`studyGenerationContract` fingerprints deployed study implementation modules. Every prepared request includes that fingerprint, the real pipeline prompt, scoped evidence and provider response schema, output budget, draft ID and request ID. The MCP is a thin HTTP transport and does not bundle a second prompt/schema pack. Pipeline changes invalidate pending requests; an agent must fetch next again. Protocol-breaking changes still require a client release.

`processStudyStep` runs the same mapping, outline, chapter, quality review, correction and activation code for both modes. Local preparation checkpoints the exact generation callback inputs; local submission resumes that callback with the supplied response. Existing schema, citation, minimum teaching content, visual contracts, arithmetic checks, meta-question rejection, one automatic correction and final source-access checks all run. Semantic review is computed by the local agent in a fresh critique context and saved with `generation.semanticReview=local-agent`; this is not independent platform/editorial review. Equal contracts cannot guarantee equal model capability.

Local drafts use `local-ready`, `local-running`, and `waiting-local` statuses. Hosted workers, including older deployments that only pick queued/running statuses, cannot claim them. No platform generation model or embedding call is made. Hosting/storage requests and the local agent’s own model/subscription usage remain separate costs.

Prepare/submit are owner and programme scoped, require write access, and recheck source availability. Mutation leases fence concurrent steps, pause, refresh and expired workers. Exact repeated submissions return saved receipts; changed responses under the same request ID are rejected. The request ID and contract are checked again inside the atomic claim. Receipts are bounded to 240; beyond that, old replays remain stale rather than creating work. Nothing automatically shares or publishes a guide.

Verification: unit tests exercise a complete local run, repeated submissions, stale contracts, ownership/source revocation, schema/citation/teaching rejection, correction prompts, hosted-worker exclusion and billing separation. Stdio MCP tests verify the exported tools and required fields. Browser tests start local generation through the real HTTP API and confirm the resumable reader state without a billing request. Model-generated content quality still depends on the local model and honest semantic review; synthetic fixtures do not prove real-model outcomes.
