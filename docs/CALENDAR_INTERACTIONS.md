# Calendar interaction refinements

Attendance marks immediately update the selected event, grid and local attendance counts. Saving uses the existing revision-checked API; the background calendar reload is no longer on the critical interaction path. A failed save restores only the affected event and its counters and shows an actionable error. A late response cannot select an event the student has since left or overwrite a newer attendance write. Requests time out after 20 seconds; concurrent writes remain serialized because the academic workspace has one revision.

Clicking a calendar event or selecting a day reopens the detail rail, even if the student previously collapsed it. Course colors are deterministic across event IDs and course years. Unmarked events use six restrained pastel course tints; attended, missed and excused use green, rose and amber fills. The course signal edge remains, mandatory attendance retains blue emphasis, and text labels convey statuses without relying on color. Exam/deadline emphasis remains rose. The same fills apply to agenda rows.

Verification includes unit coverage for targeted optimistic updates, rollback without undoing another event, clearing marks, completed-session counters and stable course colors. Browser fixtures delay the save response to prove the mark renders before acknowledgement, test selection changes during saving, simulate a revision conflict and verify rollback, reopen a manually closed rail, retain obligation filtering, and inspect desktop/mobile layouts. These tests use synthetic records and do not mark attendance on a real account.

Calendar legend items are selectable filters. No selected chips means all events; multiple chips combine with OR, while calendar-source visibility still applies. Mandatory sessions remain selectable even when attended. Exams/deadlines include completed Canvas submissions, retaining their status. The day desk uses the same filtered event set.

Canvas deadlines were being retrieved but clipped by the 07:00–22:00 week/day grid when due at 23:59. The display now projects deadlines into the top day strip using the viewer's local date and shows `Due HH:mm`. The underlying event and sidebar retain the exact timestamp; no due date is changed and the event is not represented as an all-day obligation in stored data. Ordinary sessions and exams remain timed.
